# @deepseek-ai/dsh-tool-attachment

[English](README.md) | 中文

## 概要

`dsh-tool-attachment` 提供 `attachment_paths`：它把人类用户的附件与基于路径的工具所读取的文件系统路径连接起来，是面向模型的桥梁。附加的图片只以像素形式到达模型——其持久引用是不透明的——因此图片编辑器、文件读取器或 shell 命令都没有可打开的对象。该工具通过已挂载附件存储的宿主路径访问器，解析最近一条携带附件的用户消息中的图片与文件，并连同展示元数据一起返回路径。它不复制、不写入任何内容。

## 使用本包

在挂载了 `tools` 与宿主文件后端 `attachments` 存储的 agent Cordis 组合中挂载它：

```yaml
- name: '@deepseek-ai/dsh-tool-attachment'
```

未挂载附件存储时，插件可以加载但不注册任何工具，与 `read_image` 的组合条件式注册保持一致。

### 该工具的行为

`attachment_paths` 不接受参数。它从调用会话的 surface 向前回溯，找到最近一条来自人类、且携带 `image` 或 `file` 内容块的 `user/message`，通过 `ctx.attachments.imageHostPath` / `fileHostPath` 解析每一项，并返回消息序号以及每个附件一条记录：类型、绝对宿主路径、名称、媒体类型、字节数与图片尺寸。若不存在这样的消息，则返回空列表并明确说明。

返回的路径是只读的存储副本：图片解析为规范化对象（`<dshHome>/attachments/v1/objects/<xx>/<sha256>`，无扩展名，可能经过重新编码），文件解析为逐字节保存的命名副本（`<dshHome>/attachments/v1/files/<xx>/<sha256>/<name>`）。可直接传给读取文件的工具；如需修改，请先复制。

## 模型体验

### 请求上下文与适用条件

只要组合挂载了本插件，schema 就会为每个会话注册，并在每次请求的工具目录中列出。该工具恰好在用户附加了图片、且模型需要路径时有用：附加的非图片文件已经在对话中获得带保存路径的句柄（`fileHandleText`），而附加图片除此之外没有任何路径。

### 模型看到的内容

描述中写明了触发条件（"用户附加了图片且基于路径的工具需要它"）以及路径的只读性质。调用成功时返回一个文本块：一行标题、每个附件一行（带引号的绝对路径与元数据），以及只读说明。附件字节不会进入消息；结果大小仅受单条消息的附件数量限制。

### Token 影响

每个挂载的 agent 一份工具 schema，调用时每个附件一行简短结果。其他请求不会增长。

## 已知限制与后续工作

- 该工具只报告最近一条携带附件的用户消息；更早消息中的附件需要该对话中已经回显的路径，或手动复制。
- 若附件存储并非宿主文件后端，则无法解析路径；每条记录会说明没有可用的宿主路径。
- 仅覆盖图片与文件内容块；其他内容类型没有路径形式。
