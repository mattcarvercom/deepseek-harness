# @deepseek-ai/dsh-client-ui-readaloud

[English](README.md) | 中文

## 概述

使用本包可以让 dsh web 客户端在浏览器内朗读助手回复。每条已完成的助手消息获得一个朗读按钮，朗读期间变为停止控件；开始任何一次朗读都会停止其他朗读。通用设置区获得一个「自动朗读回复」行（默认关闭）：每轮定稿后朗读该轮最后一条助手消息，新轮开始时停止播放。语音由所引入（vendored）的 sanotts 运行时在专用 worker 中于设备上合成，并按块流式播放：第一句就绪即开始朗读，其余内容继续合成；停止会取消这些合成工作。没有服务器、没有 Python、除页面自身源之外没有任何网络请求；默认音色是 `heart`。

<a id="use-this-package"></a>
## 使用本包

朗读按钮位于助手消息操作行中，介于复制与分支按钮之间，并出现在每个已定稿工作步骤的文本旁。其提示文字为「朗读」（英文：Read aloud）；消息正在合成、播放或暂停时，按钮变为实心停止图标，提示文字变为「停止朗读」。再次按下它——或开始页面上任何会话的另一次朗读——都会停止它。没有可朗读文本的消息（完全没有文本，或只有围栏代码块）在操作行中渲染不可用按钮：它不能被按下，并有一条本地化说明解释原因；没有可朗读文本的工作步骤则完全不显示控件。若合成失败，行下方出现一条本地化状态提示，直到用户重试。朗读过程中，正在朗读的句子块会在原文处高亮；朗读停止、失败或结束时高亮立即清除，暂停时高亮停留在原处。侧边栏会在正在朗读的会话标题旁显示一个脉动的小喇叭，因此在语音继续播放时切换到其他会话阅读，也始终知道声音来自哪里。

该偏好有两个入口：通用设置中的「自动朗读回复」行（标题、描述、开关；默认关闭），以及输入框工具行中、紧邻模型选择器的紧凑「自动朗读」切换芯片。同一行还会在该会话朗读时出现暂停/继续芯片与停止芯片——包括尚无消息行的流式朗读；侧边栏的会话喇叭点击即停止朗读，且不会打开该会话。暂停会保留位置：音频就地停住，继续时从剩余文本的下一个词边界接着读，因此长朗读经得起切换会话——离开会话会暂停其朗读，返回时提供继续芯片，并先补读离开期间定稿的剩余文本。开启后，正在生成的回复会边生成边朗读：模型仍在书写时，每个完整句子就开始播放；长句超过 120 字符的流式预算时按最后一个分句标点切开——没有分句标点才退回词边界——既避免单个长句拖住首次发声，也让每段的收尾落在自然停顿处；正在朗读的句子随播放高亮（在持久消息 id 出现前使用生成步骤的节点键）；步骤定稿时朗读剩余部分；没有保存消息的中断步骤也会被朗读。自动朗读只针对当前打开的会话所亲眼观察到的生成过程：切换会话而挂载既有消息时不会朗读。正在朗读的句子会持续高亮，包括回复仍在生成的阶段。开始新的朗读不会立刻掐断正在播放的声音：流式朗读会让上一段语音继续播放，直到自己的首个音频块排定后才交接。若投影无法续接（重试改写），余下内容交还给定稿自动朗读。开启后，每条已定稿的助手消息都会在其定稿节点到达时被朗读一次——即转录对图片所使用的同一个稳定信号——因此运行中的回合会逐步旁白，新的步骤会接替上一条朗读，最后朗读收尾回复。偏好后来才被打开、或消息被重新挂载时都不会再次朗读。开始新一轮会停止上一轮留下的播放。该偏好通过标准用户设置机制持久化：在环回（loopback）主机上持久保存，否则保存在进程内存中——两种方式下都能存活页面刷新。

本包只朗读用户可见的文本：它把消息的 markdown 投影为纯文本，并完全跳过围栏代码块；推理、工具调用、轨迹和系统文本从不被合成。图片块读其替代文本，链接读其标签，表格读为纯单元格，原始 HTML 原样透传。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节 — 点击展开</summary>

两个页面级单例服务所有会话，每个会话的表层构建在它们之上。

### GPL 边界

sanotts 运行时是 GPL 许可的，被刻意排除在模块图的打包之外：一个专用 Blob worker 在首次使用时动态导入 `<document base>sanotts/index.js`，`assetBase` 与 `voiceBase` 都指向同一个自托管目录。worker 中没有 `document`，而运行时以 script 标签注入其 Emscripten 模块，因此 worker 主体安装了一个极简垫片，其 `appendChild` 映射到 `importScripts`；运行时的全局检查随后与在页面中一致。显式传入 voice base 就是无网络保证——运行时的 CDN 回退只在未给 base 时才会被咨询。Vite 构建把 `assets/sanotts/` 逐字节复制到 `dist/sanotts/`，`frontend-static` 以 `application/wasm` 提供 `.wasm`，因此所有请求都是同源。播放使用原生 `AudioBufferSourceNode`；运行时自带的 `playAudio` 从不被调用。GPL 与 MIT 声明文件存放在 `assets/sanotts/` 内，与其许可的代码和音色权重放在一起。

### 引擎与导演

worker 只加载一次运行时，并缓存 wasm 模块与每个音色的权重；加载失败会被移除，下一次请求重试。引擎把长语句切分为至多 120 字符的句子块——nano 音色的 62 符号前端每次调用至多接受 207 个音素 token，而文本约每字符产生 1.1 个 token——`stream` 随每块就绪逐个产出其波形，因此首块即可开始播放，其余由 worker 继续合成。若某块的 token 数仍超出上限（字符数无法约束路径式 token 与符号串的音素数），该块会在中点处继续拆分并在产出前重试各分片。投影输出的每一行——标题、列表项、段落行——各自成块，结构边界始终是块边界；句子在预算内尽量合并，超过预算的句子按最后一个分句标点拆分（标点留在分句末尾），没有分句标点才退回词边界，因此每段都停在能自然停顿的位置。每次合成都带有约 300 毫秒前导静音与 400-500 毫秒尾部静音；引擎将前导裁到一段短的起音保护，尾部裁到 400 毫秒的句末停顿（句子续接到下一块时为 150 毫秒），使相邻块衔接不再出现突兀的空白。每块携带其在可朗读文本中的跨度，导演把该跨度经投影映射回 Markdown 源范围并随播放状态发布，ui-chat 据此渲染原文内高亮。导演拥有一个惰性创建的共享 `AudioContext`——在 `speak()` 内创建，因此手动点击出生在一个用户手势内，并在每次播放时恢复——以及至多一次进行中的朗读；它把每块依次排到前一块之后，并将已排期音频上限设为 300 秒。代数令牌丢弃那些在落地之前请求已被取代的块；`stop()` 取消进行中的合成（终止 worker，下次朗读会在数十毫秒内启用新的 worker），并对播放中和仍在合成中的请求都发布静止状态。`pause()` 就地停止已排期的音源并保留位置——当前发声块的未播放余量按下一个词边界切出后放回队首——`resume()` 从那里重新排队；离开会话会暂停其朗读而非结束它，旁白器按会话保留投影进度，因此离开期间定稿的回复会把剩余文本补入暂停的朗读。

### 每会话表层与偏好

每个会话拥有已朗读消息集合（失败的朗读也计入，因此自动朗读跨重新挂载至多每条消息一次）和一个供其消息条目订阅的播放快照存储。自动朗读偏好是一个页面级快照存储，由设置范围绑定驱动：写入先生效于实时值、再持久化；订阅时的采纳从不写回；Node 半部向设置服务注册 `ui-readaloud` 命名空间（`autoRead` 布尔值，默认 `false`）。

### 可朗读文本

`speakableText` 取消息的文本块，拼接后按 GFM 围栏规则剥离开栏代码（三个或更多匹配的反引号或波浪号、行首零到三个空格、闭合围栏长度不小于开头；结尾未闭合的围栏截断到消息末尾），再把剩余部分交给共享的 GFM 纯文本投影。四空格缩进的代码不是围栏，因此按裁剪后的源码朗读；投影会修剪每行并合并连续空行，所以剥离步骤遗留的空行永远不会到达朗读。

</details>

## 已知限制与推迟的工作

<a id="known-limitations-and-deferred-work"></a>

这些是当前包的约束，每一条都记录在承载它的地方。

- **浏览器自动播放策略** — 在用户尚未做任何手势的页面上，部分浏览器会把共享 AudioContext 保持在挂起状态，因此首次自动朗读可能无声，直到下一个手势解锁它；手动朗读出生在其点击手势内，不受影响。
- **五分钟合成上限** — 超过 300 秒的朗读会被截断；导演在达到上限后停止排期后续块，若某块恰跨过边界则丢弃其尾部。
- **缩进代码会被朗读** — GFM 四空格缩进代码不是围栏，因此按裁剪后的源码朗读；只有围栏代码块被跳过。
- **高亮粒度** — 原文高亮覆盖正在朗读的句子块并映射回其 Markdown 源；由于运行时不提供词级时间戳，并非逐词同步。
- **非环回持久化** — 在环回主机之外，设置接缝持久化在进程内存中，因此主机进程重启时偏好会重置；但页面刷新始终能存活。
- **没有音色选择器** — `heart` 是默认值，`heartnano` 是注册的低资源回退；在二者之间选择是代码改动，不是设置项。
- **原始 HTML 原样透传** — 消息中的 HTML 作为文本转发给语音引擎，而非被渲染或解释。
- **溯源压缩包随包发布** — `assets/sanotts/sanotts-web-0.3.0.tgz` 包含在 `files` 中作为钉扎记录；浏览器从不获取或执行它。

<a id="dev-note"></a>
### 开发者备注

<details>
<summary>维护者的工作上下文 — 点击展开</summary>

- **资产钉扎。** `assets/sanotts/MANIFEST.md` 记录 npm 压缩包（sha256 与 npm sha512）、音色权重来源提交，以及逐文件 sha256 表；`tests/asset-manifest.spec.ts` 在每次测试运行时把该表与目录重新对账。重新引入资产意味着重新记录该表。
- **CSP 判定。** 无需改动 CSP：主文档没有 CSP，唯一的沙箱化 iframe（`/api/file` 的媒体预览）也从不承载运行时。
- **测试接缝。** worker 主体以参数接收模块与经典脚本加载器，运行时接受 Worker 工厂，引擎接受合成运行时接缝，因此测试用假实现驱动协议、worker 缓存与流式排期，并桩掉 WebAudio 全局对象：没有任何测试合成真实音频、导入 wasm 或触碰网络；浏览器 bench 启动组装好的 web 应用，在无音频的情况下断言条目、偏好与播放生命周期。
- **升级路径。** 运行时钉在引入的 0.3.0 版本上；版本升级是一次重新引入（新哈希、新清单行），而不是依赖变更。

</details>

**运行时不变量：** 不发布伴随物。播放与偏好是建立在类型化快照存储之上的浏览器本地状态，由组件、存储与 bench 测试覆盖，没有任何 Cordis 运行时关系会在两个独立观察之间发生分歧。
