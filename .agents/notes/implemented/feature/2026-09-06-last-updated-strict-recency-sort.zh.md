# Agent Note: Last updated as a strict recency sort

Status: implemented

[English](2026-09-06-last-updated-strict-recency-sort.md) | 中文

## 问题

视图菜单的**最近更新**排序承诺的是按最近更新排序的视图，实际交付的却是另一套机制：持久化在浏览器 localStorage 中的每个记账顺序是冻结的，只有当某条 Session 的 `updatedAt` 超过持久化的已观察快照时，它才会一次性跳到最前。因此在不同时间加载同一份 Host 数据的不同浏览器各自持有不同的冻结顺序，同一个选项在不同浏览器中合法地渲染出不同的列表。标签写的是排序，行为交付的却是浏览器本地历史。该模式下的拖拽编辑的是一份标签已无法描述的顺序，而一次性置顶也无法用用户看到的任何东西解释。

## 决策

**最近更新**现在是渲染时计算的严格最近更新排序：`updatedAt` 最新者优先，以稳定的 Session id 作为平局决胜。该排序作用于分组呈现中每个 Workspace 分组的成员和 Ungrouped 桶，以及单列表。显示是 Host session 列表的纯函数，因此在每个浏览器中完全一致，首帧渲染的就是最近更新时间顺序而不是过期的持久顺序，并在活动时间戳变化时立即重新排序。

该模式不持久化任何内容。持久化的每个记账 Session 顺序（`dsh.workspace.view.v6` 下的 `sessionOrderByAccount`）只在选中**手动排序**时被读取和写入：浏览器把每个记账的存储排列与其当前成员对账——按记账顺序追加新 id、丢弃消失的 id——仅在发生变化时写回。切换到最近更新不会触碰存储的排列；切回手动排序会精确恢复它，因此模式往返在两个方向上都是无损的。

Session 拖拽仅限手动排序模式。最近更新激活期间，session 行不可拖拽，因为该模式下的放置会被每次渲染的重新排序遮住。手动模式下的拖拽行为不变：真实 Workspace 的拖拽写入浏览器本地记账和 Host Session 记账，而 Ungrouped 和单列表的拖拽保留在浏览器本地。

一次性置顶机制已被移除：持久化的 `sessionUpdatedAtByAccount` 已观察时间戳、切换到最近更新的重新排序标志、以及按活动的置顶分支都已从 store 和浏览器中删除。持久化键保持 `dsh.workspace.view.v6`：携带现已惰性的 `sessionUpdatedAtByAccount` 键的移除前负载可以无害地重新水合，因此无需升键。两个最近更新比较器现在对相同 id 返回零，保持比较器契约的完备性。空白“新会话”的一次性创建时置顶（不推进 `updatedAt`）在其分组记账和单列表记账中保留：它为手动排序安排行位置，并在最近更新渲染最近更新时间排序期间对显示无影响。

视图菜单标签**手动排序**和**最近更新**保持不变；最近更新现在与其标签相符。

## 考虑过的替代方案

**保留置顶语义并修复跨浏览器分歧。** 在冻结顺序之上的置顶不可避免地依赖浏览器历史：同一个选项仍会在不同浏览器中显示不同的列表，标签仍会过度承诺排序。

**为最近更新单独持久化每记账的第二份顺序。** 显示将读取持久顺序而不是数据，重新引入首帧过期和第二套记账流，并且存储的是数据投影而非任何用户排列。

**在 session 无变化时隐藏排序菜单。** 该选项将在一种模式下失去意义，菜单将成为条件化的界面元素，而用户本就可以在行中直接看到这个差异。

## 后果

- 最近更新在每个浏览器和两种呈现中都是真正的最近更新排序；选项与其标签相符，活动时间戳在列表刷新时立即移动行。
- 手动排序在模式切换和重载后保持其精确排列；一次最近更新的偏离不再打扰它。
- Session 拖拽从最近更新的呈现中消失。想通过拖拽固定行的用户必须切换到手动排序；被移除的拖拽外观是唯一丢失的交互。
- 视图 store 失去一个持久化字段。携带它的既有 v6 负载以惰性键重新水合；无需迁移或升键。
- [Workspace 侧边栏顺序与折叠](2026-08-11-workspace-sidebar-order-and-folding.zh.md)确立的一次性“新会话”置顶和手动模式拖拽语义保持不变；该笔记中的置顶句子由本决策取代。

## 测试

UI 测试固定新语义：存在过期存储排列时，最近更新的显示是严格最近更新排序——Workspace 分组、Ungrouped 桶和单列表均覆盖——且该模式不触碰持久顺序、把行标记为不可拖拽；用户活动在不写 store 的情况下重新排序显示；切回手动排序恢复存储排列并在重新挂载后持久化。store 规格固定被移除字段的缺席、双参数 `syncSessionOrderAccount` 以及无时间戳映射的保留。workspace-management Web e2e 仍固定 v6 持久化键。
